# 画像保存ツール

ログインが必要なサイトのメディア一覧をブラウザで操作し、写真・動画・音声を保存する Windows 向けツールです。

## 目的

ユーザーがブラウザでログインして開いたメディア一覧を利用し、選択した種類のメディアを順番に保存します。

## 想定する利用方法

1. ツールから Edge または Chrome を起動する
2. ユーザーがブラウザ上で手動ログインする
3. ユーザーが対象メンバーのメディア一覧と、保存したい種類のタブを開く
4. ツールで同じ種類を1つ選び、取得を開始する
5. 写真・動画は画面座標で順にクリックして保存する
6. 音声は一覧の各行中央を1回ずつクリックして保存する。音声では Escape を送信しない

パスワードはツールに保存しません。

## 初期要件

| 分類 | 要件 |
| --- | --- |
| 認証 | 初回のみユーザーが手動ログインする |
| セッション | ログイン状態を保存し、次回以降に再利用する |
| 対象 | ユーザーがブラウザで開いたメディア一覧 |
| 一覧 | 無限スクロールに対応する |
| メディア | 写真・動画・音声を種類ごとに取得する |
| 保存先 | 指定したフォルダの下に種類別フォルダを作成する |
| 制御 | 最大保存件数、スクロール間隔、停止操作を指定できる |
| 重複 | 同じ画像を重複保存しない |
| エラー | 失敗した画像を記録し、可能な限り処理を継続する |
| 配布 | 最終的に Windows の `.exe` として実行できる |

## 技術方針

**Python + Playwright** を使い、Chrome DevTools Protocol (CDP) でユーザーが開いたブラウザへ接続します。ブラウザ起動後のログイン、メンバー選択、メディア一覧や写真・動画・音声タブへの移動はユーザーが行います。1回の実行で取得できる種類は1つです。GUIでも同じ種類のタブを先に開き、対応するチェックボックスを1つだけ選択してください。

写真一覧のスクロール量は、画面高さの70%を基準に15%増やし、さらに10%増やしています（画面高さの約88.55%）。

写真は `/files/` 配下の `.jpg` / `.jpeg` かつ `image/jpeg` のレスポンス本体を保存します。動画は `video/mp4` のレスポンス本文を取得して `.mp4` で保存し、ファイル保存が完了した場合にだけ Escape で閉じます。動画応答がない場合は待ち時間を最大2秒として次の地点へ進み、本文を取得できたが完全なMP4として保存できない場合は画面遷移を避けて処理を中断します。写真・動画は画面中央の4列を座標で走査します。音声は画面中央の各行を1回クリックし、`audio/mp4` または `video/mp4` のレスポンスを音声ファイルとして保存します。音声のクリックでは Escape を送りません。保存先には `photo`、`video`、`audio` フォルダーを作成します。写真の走査は1画面あたり最大43地点、スクロール量は画面高さの約88.55%です。音声の走査は1画面あたり最大7行です。ブラウザのログイン Cookie、Referer、User-Agent、一時 URL などを含む現在のブラウザセッションを利用できます。

## 段階的な開発計画

### Phase 1: 取得方式の検証

- ツールからブラウザを起動する
- 手動でログインし、対象画面まで開く
- 写真・動画・音声のタブを開き、対応する種類を保存する

### Phase 2: 一覧処理

- 表示中の画像を検出する
- 未処理画像をクリックする
- 一覧を一定量スクロールする
- 新しく表示された画像を検出する
- URL やサイト上の識別子で重複を除く
- 最大件数と停止操作に対応する

### Phase 3: GUI

- ブラウザ起動ボタンと利用手順の表示
- 写真・動画・音声の取得選択
- 保存先フォルダの選択
- 開始・停止ボタン
- 成功件数、失敗件数、処理状況の表示

### Phase 4: 配布

- Windows `.exe` 化
- 初回ログイン手順の整備
- エラーログと設定の保存

## 先に確認する事項

対象サイトごとに、以下を検証してから本実装を進めます。

- Network の画像リクエストの Content-Type が `image/*` になっているか
- 画像 URL のパスに拡張子や一意な ID が含まれているか
- 高解像度画像のレスポンス本体を保存できるか
- 一覧画面を開いた時点で取得される画像と、スクロール後に取得される画像を区別できるか
- スクロールによる追加読み込みの完了を判定できるか
- Chrome のログインセッションで画像レスポンスを保存できるか

対象サイトの利用規約、著作権、アクセス制限を守って利用します。大量アクセスを避けるため、取得間隔と処理件数を制御できるようにします。

## Phase 1 の実行

Python 3.11 以上を用意し、プロジェクトのルートで以下を実行します。

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e .
playwright install chromium
```

GUIではブラウザ起動ボタンを押して Edge または Chrome を起動します。開いたブラウザで手動ログインし、対象メンバーのメディア一覧と取得したい種類のタブを開いてください。下の種類選択では1つだけチェックして実行します。コマンドラインから直接実行する場合は、ブラウザをリモートデバッグ対応で起動してから以下のコマンドを使います。

```powershell
& "$env:ProgramFiles\Google\Chrome\Application\chrome.exe" `
	--remote-debugging-port=9222 `
	--user-data-dir="$PWD\.data\chrome-profile"
```

```powershell
python -m app.phase1 `
	--cdp-url "http://127.0.0.1:9222" `
	--mode photo `
	--output-dir output
```

`--mode` は `photo`、`video`、`audio` のいずれかです。写真・動画は画面上の4列を座標で走査し、音声は各行の中央を1回ずつクリックします。写真・動画は成功後に Escape で閉じますが、音声では Escape を送りません。保存先の下に種類別のサブフォルダーが作成されます。
