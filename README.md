# 画像保存ツール

ログインが必要なサイトの画像一覧をブラウザで操作し、画像クリック後に取得できる高解像度画像を保存する Windows 向けツールです。

## 目的

ブラウザ上では直接保存できない画像について、ユーザーがログインした状態を利用して、画像一覧から高解像度画像を順番に保存します。

## 想定する利用方法

1. ユーザーがリモートデバッグ対応の Chrome を起動する
2. ユーザーがブラウザ上で手動ログインする
3. ユーザーが対象の画像一覧画面まで開く
4. ツールが一覧のサムネイルを一枚ずつクリックする
5. 写真を開いたときの高解像度画像レスポンスを保存し、写真ビューを閉じる

パスワードはツールに保存しません。

## 初期要件

| 分類 | 要件 |
| --- | --- |
| 認証 | 初回のみユーザーが手動ログインする |
| セッション | ログイン状態を保存し、次回以降に再利用する |
| 対象 | ユーザーが指定した画像一覧ページ |
| 一覧 | 無限スクロールに対応する |
| 画像 | クリック後の高解像度画像を保存する |
| 保存先 | ユーザーが指定したフォルダ |
| 制御 | 最大保存件数、スクロール間隔、停止操作を指定できる |
| 重複 | 同じ画像を重複保存しない |
| エラー | 失敗した画像を記録し、可能な限り処理を継続する |
| 配布 | 最終的に Windows の `.exe` として実行できる |

## 技術方針

初期実装では **Python + Playwright** を使い、Chrome DevTools Protocol (CDP) でユーザーが開いたブラウザへ接続します。ユーザーのログイン操作や対象画面への移動は自動化しません。

写真一覧のスクロール量は、画面高さの70%を基準に15%増やし、さらに10%増やしています（画面高さの約88.55%）。

サムネイル画像ではなく、クリックして写真を開いたときに発生する `/files/` 配下の JPEG レスポンス本体を保存します。画面中央の最大430px幅をクリック対象とし、上端1/8を除外して4列を下から上へ走査します。縦方向は細かい間隔で最大11行、1画面あたり最大43地点をクリックしてから上へスクロールします（48地点から約10%削減）。スクロール量は画面高さの70%を基準に15%増やし、さらに10%増やしています。同一走査中、JPEG応答を得た画像付近の重複クリックは避けます。JPEG応答後は表示更新を待ってEscapeで写真ビューを閉じ、応答から次のクリックまで最低0.5秒空けます。応答がないクリックでは次の座標へ進みます。保存先に同じファイル名が存在する画像は再保存しません。スクロール後は新しいサムネイル通信を待ち、変化がない場合は段階的に最大8秒まで待機し、複数回の確認後に終了します。これにより、ログイン Cookie、Referer、User-Agent、一時 URL などを含む現在のブラウザセッションを利用できます。

## 段階的な開発計画

### Phase 1: 取得方式の検証

- 手動でブラウザを起動する
- 手動でログインし、対象画面まで開く
- Network に発生する画像レスポンスを監視する
- 画像レスポンスを一枚ずつ保存する

### Phase 2: 一覧処理

- 表示中の画像を検出する
- 未処理画像をクリックする
- 一覧を一定量スクロールする
- 新しく表示された画像を検出する
- URL やサイト上の識別子で重複を除く
- 最大件数と停止操作に対応する

### Phase 3: GUI

- 対象ページ URL の入力
- 保存先フォルダの選択
- 最大保存件数の指定
- スクロール間隔の指定
- 開始・停止ボタン
- 成功件数、失敗件数、処理状況の表示

### Phase 4: 配布

- Windows `.exe` 化
- 初回ログイン手順の整備
- エラーログと設定の保存

## 先に確認する事項

対象サイトごとに、以下を検証してから本実装を進めます。

- Network の画像リクエストの Content-Type が `image/*` になっているか
- 画像 URL のパスに拡張子や一意な ID が含まれているか
- 高解像度画像のレスポンス本体を保存できるか
- 一覧画面を開いた時点で取得される画像と、スクロール後に取得される画像を区別できるか
- スクロールによる追加読み込みの完了を判定できるか
- Chrome のログインセッションで画像レスポンスを保存できるか

対象サイトの利用規約、著作権、アクセス制限を守って利用します。大量アクセスを避けるため、取得間隔と処理件数を制御できるようにします。

## Phase 1 の実行

Python 3.11 以上を用意し、プロジェクトのルートで以下を実行します。

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e .
playwright install chromium
```

通常の Chrome をすべて終了した状態で、専用のユーザーデータフォルダを指定して起動します。既存の Chrome を閉じたくない場合は、別の `--user-data-dir` を使用してください。

```powershell
& "$env:ProgramFiles\Google\Chrome\Application\chrome.exe" `
	--remote-debugging-port=9222 `
	--user-data-dir="$PWD\.data\chrome-profile"
```

開いた Chrome で手動ログインし、対象の画像一覧画面まで移動します。別の PowerShell で次の監視を開始します。

```powershell
python -m app.phase1 `
	--cdp-url "http://127.0.0.1:9222" `
	--media-list-url "https://example.com/media-list" `
	--mode photo `
	--output-dir output
```

ログイン済みの Chrome に接続後、選択したメンバーの一覧URLへ移動し、そのURLと一致することを確認してから処理を開始します。最大430px幅の中央領域について上端1/8を除外し、4列を下から上へ最大43地点クリックした後、上へスクロールします。スクロール量は画面高さの70%を基準に15%増やし、さらに10%増やしています。写真JPEG応答の後は表示更新を待ってEscapeを送り、次のクリックまで最低0.5秒空けます。写真応答がないクリックの待ち時間は既定値1秒です。URL のパスに `/files/` を含み `.jpg` または `.jpeg` で終わる `image/jpeg` レスポンスを `output` に保存します。同じファイル名が保存先にある写真は再保存しません。スクロール後は新しいサムネイル通信を待ち、変化がない場合は段階的に最大8秒まで待機してから再確認します。Flutter画面上の画像個々の境界をPlaywrightが取得する方式ではなく、画面寸法に基づく座標操作です。
